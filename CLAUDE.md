## Request flows

- **Chat (RAG):** retrieval happens entirely in the browser. `store.ts` `buildIndex()` chunks the bundled profile + posts (`rag.ts` `chunkParentChild`: ~300-word parents, 60-word children, 15 overlap) → `ChatBox.tsx` runs `rerank(retrieve(query, getIndex()))` → only the top chunks go to `POST /api/chat`. The server clamps that client-supplied context (`MAX_CONTEXT_CHUNKS`, `MAX_CONTEXT_CHARS` in `index.ts`) because the endpoint is public and bills OpenRouter. With no LLM configured, no hits, or a failed call, the UI answers with `fallbackAnswer()` (raw retrieval + citations) and never calls the model. Cost guards: `OPENROUTER_MAX_TOKENS`, `temperature: 0.2`, a 24 h per-instance answer cache keyed by question + context (`index.ts`), and a per-visit cache in `ChatBox`. `rag.ts` `prepare()` tokenizes an index once (WeakMap), so a query doesn't re-tokenize the corpus. The index is rebuilt in memory; `localStorage` only stores sync metadata (`SyncButton`).
- **Profile edit:** `ProfileEditor` → `PUT /api/profile` (admin) → server reads `profile.json` from GitHub, merges `sanitizeProfile(input)` over it, and commits it with the file's `sha` → GitHub Actions redeploys. The live site changes only after the rebuild, because `getProfile()` serves the copy bundled at build time.
- **Avatar:** `PUT /api/profile/avatar` checks magic bytes (`sniffImage`) and stores each upload as its own version, `assets/avatars/{v}.{ext}`. The profile stores `/api/avatar?v={v}`, so an upload changes nothing on the live site until a profile save commits that URL, and one URL always serves the same bytes (cached as immutable). Uploads and profile saves prune every object nothing points at. An upload keeps the new version and the committed one. A save keeps only the committed one, so the previous avatar, including the pre-versioning `assets/avatar.*`, goes as soon as a new one is saved. If GitHub can't be read, nothing is pruned. An unknown `v` falls back to the legacy object, else the newest version (served `no-cache`), which covers the minute before a redeploy ships the new URL. The URL origin comes from `publicOrigin(req)`, which is why `TRUST_PROXY` matters.
- **Landing page:** `Home` in `App.tsx` builds every section from `profile.json` (`available`, `skills` and `stats` are optional; an empty one hides its section). `sanitize.ts` must allow-list any new profile field, or an admin save drops it. `avatar` may be a bare `public/` filename. Visuals: `Backdrop` (fixed scene behind every page), `Portrait` (pointer tilt) and `Landing.tsx`. One motion switch, `lib/motion.ts`, sets `html[data-motion]`, which both CSS and the JS loops read. Scroll reveals use `[data-reveal]` plus `useReveal()` in the page component. **Performance rule (measured, the first version lagged):** nothing may animate continuously except `transform`/`opacity` on plain layers. No `filter: blur`, `backdrop-filter`, `mix-blend-mode`, mask or canvas redraw on anything that moves or sits over something that moves: each one made the GPU re-composite full-screen layers every frame. The backdrop is one static element, so add looks as background layers, not as animated children.
- **Comments:** Blob layout is `comments/{slug}/{id}.json`, private access, and every read is proxied through the API. Every write also rewrites `comment-versions/{slug}.json`. Reads go `threadVersion()` (one `head`) → `readThread()` (cached per instance by version; `list` + `get`s only when the version moved). `updateComment` reads the single comment fresh. Reactions are read-modify-write, done with `useCache: false`. `parseComment` rebuilds each object field by field and skips malformed ones.

## Backend patterns (`server/src/index.ts`)

- One `handle()` function matches routes with `method` + `path` `if` checks. Throw `HttpError(status, msg)` for expected outcomes; the top-level catch turns it into `{error}` JSON. Any other throw is logged with its stack as a 500.
- Guards: `requireAdmin(req)` (verifies the HMAC token from `auth.ts`), `requireStorage()`, and `llmReady()`. A missing config group should answer 503 instead of crashing.
- Rate limiting is an in-memory `Map` per instance (`rateLimited(key, limit, windowMs)`, keyed by `clientIp`). On serverless it's best-effort only.
- JSON bodies are capped at `MAX_JSON_BYTES` (16 KB); the avatar uses `env.limits.avatarMaxBytes`.
